## Media File Processing flow
Each file should be processed in this order. Tools can depend on eachother and can call helpers. See dependencies for each tool below.

The tools/media-manager/ coordinates and executes these tools:

1. tools/renamer/
2. tools/kirtan-splitter/
3. tools/class-discoverer/
4. tools/content-discoverer
5. tools/class-trimmer/


## Pipeline behaviour
- Each tool runs on its own (single file or batch) or chained by the media manager.
- A flagged file pauses on its own; other files continue. After approval it resumes at the next step.
- Kirtan-only outputs are `Skipped` for class-discoverer, content-discoverer and class-trimmer.
- File statuses and the full rules are in @SPEC.md (sections 4 and 7).

## Enriching the filename and Baserow
When a tool discovers new metadata (date, WHAT, place, ...), it does not rename files itself: it queues the Renamer with that evidence (`params={"evidence": {...}, "source": ...}`, see tools/renamer/SPECS.md). The Renamer keeps values a person confirmed, fills the gaps, and flags conflicts for review.
