## Goals
This helper is responsible for connecting to Baserow and performing CRUD actions when called by other tools. This helper should keep an activity log and should report errors. It should also be resilient against disconnects and other network problems. The Baserow credentials are available in /.env.

## Requirements
- Connect to our Baserow media database. The credentials, media database and tables are available in .env
- Read, Create, Update and Delete media items in the media table
- add a dry-run mode
- Will be called from other tools in this project
- Changes in the review portal will be processed by this helper
- Only use the available columns
- Only use the available options in single/multiselect columns
- Notify user when new countries/locations are required. A new place is added as a `place_location` option in Baserow; its country goes in the `place_country` table (the portal adds it when a person saves a file). The travel schedule is never written.

## Database and table information
The .env provides the database name and relevant tables. The important tables in the "media-db" database are:

- media: This contains all the verified media items
- travel-schedule: the travel schedule of Kadamba Kanana Swami. It provides clues and sometimes evidence for date and locations
- category_filename_folder: Provides the media categories, filename search terms, folder names and their colour scheme.
- place_country: one row per media `place_location` option with its country. This is the only link between a place and its country.

### Tables to ignore
- users
- media_review_tasks

# READ (search)
Search for existing items by matching the date, category place_location, title or other columns.

Matching rule for an existing recording (see SPEC.md section 6): the same date is required but never enough on its own. The row must also agree on the verse `tag` and/or the `title`; `place_location`, `country` and `category` add evidence, and a different verse, place or country counts against it. Several fitting rows: flag for review.

# UPDATE
Update an existing media item with newly discovered metadata. 

# CREATE
Add a new row. Use the following defaults for the columns listed below

- title
  - If there is a title in the filename, use that
  - If there is a title in the parent folder name, use that
  - If no title is available, use the filename
  - Verse numbers in a title use dots, not hyphens: `BG 2.54`, `CC Madhya 20.154` (see docs/references/verse-structure.md)
- date : Set the recording date in the format YYYY-MM-DD
- category (single select): The media category of the recording. The media category is determined by the Renamer Tool or by consecutive tools.
- tag: When a verse is mentioned in the filename add it in this field
- language (multi select): Use english as the default and add other languages when discovered
- status_media (select): Use "Not-started”
- status_thumb (select): Use “Not-started”
- youtube_link (url): link to the youtube video, otherwise leave empty
- youtube_desc: Boolean. Set to 1 when media_description is filled
- media_description: A generated description for youtube videos
- themes (text): Topics generated by the content-discoverer, separated by a comma and a space (e.g. `Krishna Prema, Kali Yuga`)
- audio_link (url): Link to the audio file online
- notes: Notes and comments from previous and current review tooling. 
- thumb_image_file: <leave empty>
- transcriber: <leave empty>
- status_transcript (single select): set to "Not-started"
- transcript_link (url): <leave empty>
- article_link (url): Linkt to article on kadabafoundation.com when published, otherwise leave empty
- alternative_links: possible links to other recordings. Useful for checking recording dates/locations
- filename_deprecated: Do not use
- audio_file_location: path and filename of audio file in the archive
- video_file_location: path and filename of video file in the archive
- transcript_file_location: path and filename of transcript file in the archive
- imported_on: Use current date YYYY-MM-DD
- Created On, Last modified, last modified by: <ignore>

## travel-schedule table scheme
Column start_date: Arrival date
Column end_date: Departure date
Column original_schedule: The original travel schedule text that was used to determine the start/end date
Column place_location: places (usually temples or city names) and recording locations.
column country: Country of recording.

## place_country table scheme
Column place_location (text, primary): exactly a media `place_location` option, e.g. `Brno`
Column country (text): a media `country` option, e.g. `Czech-Republic`; empty for general places used in many countries (Zoom-livestream, Home-program, Summercamp, Govindas)
Column ccTLD (text): the country code used in filenames, e.g. `cz`
Column Aliases (text, optional; read ignoring case, filled by hand): other spellings of the place separated by semicolons, e.g. `New-Radhakunda-Dham;NRK` on `ISKCON-Korsnäs-Gård`. The Renamer maps an alias to the place; tools never write this column.

The table id is `BASEROW_PLACE_COUNTRY_TABLE_ID` in `.env`. It was filled once with `uv run mam place-country sync` (dry run first, `--apply` to write). Afterwards the portal adds a row (or fills an empty country) when a person saves a file with a place and a country; a row with another country is never changed.

## category_terms_folder table scheme
Column category: the main media category. This is a clone from the media.category column
Column filename_terms: possible search terms that are found in filenames to match to their category
column folder_name: Final location of renamed files when the media category was determined
Column color: label color that is used in the Baserow application for each media category. Should be used in the review portal as well!

## Background information
Our media database (on Baserow) is our searchable repository of information on each recording that is available online and/or in the actual archive. All media data is stored in the “media” table and we have built an application within Baserow that is published on https://media.kadambafoundation.com.

The database already has quite a lot of recordings added, so you need to check the database if the new recording does not already exist. And there could be duplicates. It is possible that a media item in the media database has multiple formats. For example a media item can have:
Link to Youtube video
Link to the transcript
Link to online audio file
Path to audio/video file in the archive
